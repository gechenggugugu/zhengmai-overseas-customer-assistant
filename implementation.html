部署与接入说明

数据来源

演示模式里的公司、联系方式和 .example 链接都是虚构样本，仅用于体验功能，不能当作真实客户。真实搜索只调用配置的服务端接口；后端未配置或用户未登录时会报错，不会回退到演示样本。真实结果保留公开来源链接，使用前应核验。

页面现有搜索、筛选、去重、收藏、跟进历史、CSV 导出和英文邮件草稿在 Windows 本地版和线上版共用同一套业务代码。

Windows 本地运行

解压启动包后双击 start-windows.bat。它使用 Windows 自带 PowerShell 在本机启动网页并打开浏览器；不需要安装 Node.js、npm 或数据库。关闭启动窗口即可停止服务。免安装包和在线部署加载同样的页面、服务逻辑和配置文件。

启用跨设备同步时，本机也须通过 http://127.0.0.1:4173 启动，以便 ES 模块与登录回调正常工作；file:// 直接打开不支持此版本。

GitHub Pages 在线发布

正式网址：https://gechenggugugu.github.io/zhengmai-overseas-customer-assistant/。源码仓库：GitHub 项目。本项目由 main 分支根目录发布。更新源码后，在仓库 Settings → Pages 检查分支为 main、目录为 /(root)。静态演示无需环境变量或 API 密钥。GitHub 官方的分支发布说明介绍了配置方法。该仓库为公开仓库，源码对所有人可见。

邮箱登录和跨设备同步

云端功能基于 Supabase Auth 与 Postgres。先创建 Supabase 项目，执行 backend/supabase/migrations/20261126000100_lead_records.sql，部署 Edge Function，并在此文件填写项目 URL 和 publishable/anon key。该 key 会出现在浏览器中，只有配合启用的行级安全（RLS）才可公开使用；SQL 已按登录用户限制每行的读写权限。浏览器不会拿到 Supabase secret/service-role key。

配置完成后页面会显示邮箱登录表单。不同电脑登录同一邮箱账号后，收藏、跟进状态、备注和历史从同一云端记录同步。访客数据保存在原浏览器，不会自动并入账号；退出后本地缓存仍保留。

Supabase 免费层目前标价为 $0，但长期不活跃的免费项目会被暂停。无需付费升级；本次没有创建 Supabase 项目、启用付费服务或提交付款信息。请查看 当前价格与免费层限制。

真实搜索 API 与密钥

页面将登录用户查询发送到 https://<project-ref>.supabase.co/functions/v1/leads-search。Edge Function 验证 Supabase 登录会话，再请求你选择的搜索服务或自建适配器。适配器接收 { product, market, type, keyword, days, mode, limit }，返回 { leads: [...] }；每条结果需要名称和有效来源链接。项目代码提供通用适配器入口；具体供应商 API 格式需按你选定的数据服务实现，当前没有已接通的真实搜索供应商。

将 SEARCH_API_URL、SEARCH_API_KEY 和 APP_ORIGINS 配置到 Supabase Edge Function Secrets。不得将这些值写入 public-config.js、GitHub 仓库或浏览器环境变量。若之后确实接入 AI 摘要，还须在后端安全存放对应模型密钥；目前不要求 AI 密钥。

部署顺序和 CLI 操作见 后端部署说明。跨域来源要包含 GitHub Pages 的网站 origin 和本机 http://127.0.0.1:4173。
